# 交接包模板

按项目裁剪，删掉不适用的行；不要保留空占位符。方括号里是填写提示。

## 文件一：HANDOVER.md

```markdown
# HANDOVER — [项目名]

> 交接时间：[YYYY-MM-DD HH:mm]
> 交接原因：[上下文过长 / 方向重构 / 阶段完成 / 换 agent / 其他]
> 当前阶段：[阶段名]
> 新 agent 从这里开始：先读第 0 节，再读第 10 节。

## 0. 一页速览

- 一句话目标：[最终要交付什么]
- 当前状态：[一句话说清做到哪了]
- 下一步：[一句话说清第一件要做的事]
- 最大风险/阻塞：[没有就写“暂无”]
- 建议阅读顺序：[如：0 → 10 → 3 → 4]

## 1. 目标与范围

### 最终交付物

- [交付物、格式、给谁用]

### 验收标准（可检验）

- [ ] [标准，尽量带数字或可观察结果]

### 明确不做 / 不在范围

- [避免新 agent 自行扩大范围]

## 2. 当前阶段与进度

| 里程碑 | 状态 | 证据 | 备注 |
|---|---|---|---|
| [名称] | 已完成 / 进行中 / 未开始 / 阻塞 / 已废弃 | [路径、命令输出、提交号] | |

| 事项 | 状态 | 证据 | 依赖 / 负责人 |
|---|---|---|---|
| [具体工作项] | | | |

## 3. 决策记录

| 日期 | 决策 | 理由 | 被否方案 | 代价 / 约束 |
|---|---|---|---|---|
| | | | | |

只记会影响后续选择的决策，不要记流水账。

## 4. 死路与否定约束

| 不要再尝试 | 失败原因 | 证据 | 何时可以重试 |
|---|---|---|---|
| [方案 X] | [性能不足 / 逻辑死锁 / 无权限……] | [日志、实验、提交] | [条件，或“不要重试”] |

## 5. 产物地图

| 路径 | 作用 | 状态 | 是否权威 | 备注 |
|---|---|---|---|---|
| [绝对或项目内路径] | [一句话] | 完成 / 草稿 / 过期 | 是 / 否 | [以它为准的原因] |

“权威”指新 agent 遇到多个版本时应以哪个为准。

## 6. 环境与运行

- 操作系统 / 硬件：[]
- 运行时与版本：[]
- 依赖安装：[命令]
- 启动：[命令]
- 构建：[命令]
- 测试 / lint：[命令，最近一次结果]
- 外部服务与权限：[服务名；密钥位置，不写值]
- 配置文件：[路径与用途]
- 已知环境坑：[]

## 7. 数据、参数与外部状态

- 数据 / 模型 / 输入输出：[路径、版本、规模]
- 关键参数 / 超参数：[]
- 分支 / 未提交修改 / stash：[]
- 外部系统当前状态：[已部署版本、任务队列、远端差距]
- 长任务 / 定时任务：[正在运行什么，如何查看]

## 8. 已知问题与风险

| 问题 | 影响 | 证据 | 临时绕过 | 建议动作 |
|---|---|---|---|---|
| | | | | |

## 9. 未验证假设与不一致项

| 内容 | 来源 A | 来源 B | 证据 | 需要谁确认 |
|---|---|---|---|---|
| [假设或冲突] | [对话/文件/git] | [对话/文件/git] | | |

## 10. 下一步

### P0 — 立即做

- 动作：[具体到文件和操作]
- 产出：[]
- 完成标准：[]
- 依赖 / 风险：[]

### P1 — 随后做

- [同样格式]

### 不要先做

- [看起来相关但会打断主线的事]

## 11. 交接备注

- 用户偏好 / 禁令：[]
- 沟通与输出格式要求：[]
- 需要人类拍板的问题：[]

## 12. 相比上次交接的变化

首次交接写“无”。否则写：

- 新增：[]
- 变化：[]
- 失效：[]

## 13. 接手验收

- [ ] 能复述目标与验收标准
- [ ] 能指出当前状态及其证据
- [ ] 能说出至少两条死路
- [ ] 能执行 P0 的第一个动作
- [ ] 知道哪些问题必须先问人类

## 14. 证据索引

- 关键命令：[]
- 日志位置：[]
- 关键对话位置：[轮次/主题]
- 外部链接：[]
```

## 文件二：SYSTEM_PROMPT_NEXT.md

```markdown
# 接手提示词 — [项目名]

你是 [项目名] 的接手 agent。你的任务是 [一句话目标]。

开工前先读 `[HANDOVER.md 绝对路径]`。若读不到，按下面的信息开始，并先向用户说明缺少详细交接包。

## 目标与验收

- 目标：[]
- 完成标准：[]
- 不在范围：[]

## 硬约束

- [用户明确要求、不可改的接口/设定/格式]
- [必须先问人类的事]

## 当前状态（截至 [日期]）

- 阶段：[]
- 已完成：[]
- 进行中：[]
- 阻塞：[]

## 已废弃路径（不要重试）

- [方案 X：原因]

## 第一步

1. [读取/核对的第一个文件或命令]
2. [第一个实际动作]

## 工作方式

- 动手前先核对文件与 git 状态；与 HANDOVER.md 不一致时，先报告再行动。
- 只做与目标相关的最小改动，不顺手重构。
- 需要人类决定的事集中提问，不自行假设。
- 不输出、不提交任何密钥。
```
